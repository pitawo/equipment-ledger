# 備品台帳 PRO — 貸出管理アプリ

カメラや機材の貸出・返却・予約をブラウザから管理する Flask アプリ。機材を複数人で共有する場面を想定している。

![Python](https://img.shields.io/badge/Python-3.11-blue) ![Flask](https://img.shields.io/badge/Flask-3.x-black)

## できること

### 予約と貸出

- 機材を選んで期間と目的を指定し、予約する
- **同じ期間に別の予約は入れられない**（重複を検出して断る）
- 開始日は今日以降のみ受け付ける
- 日付は `12/5` のように月日だけで入力できる（過ぎている月日は翌年として扱う）

### 稼働状況の一覧

- 全機材の状態を「利用可能 / 貸出中」で表示
- 貸出中の機材は借用者・期間・目的を表示
- 予約は状態別に分かれる — **利用中 / これからの予約 / 終了済み**
- 返却はワンクリック。これからの予約は取り消しで消す

### 機材マスター

- 機材の追加・名前の変更・削除
- **予約が残っている機材は削除できない。** 利用中だけでなく、これからの予約も対象（削除しようとすると理由を表示する）

### ログイン

- メールアドレスとパスワードで登録・ログイン
- パスワードはハッシュ化して保存する（`werkzeug.security`）
- 予約の氏名はログイン中の利用者から取る（フォームの入力値は使わない）

### 通知（任意）

SMTP の設定が環境変数にあるとき、貸出・返却の通知メールを送る。未設定なら送信をスキップして動作を続ける。

## 動かす

```bash
pip install -r requirements.txt
python app.py
```

`http://localhost:5000` が開く。**初回起動時は `equipment_data_sample.json` から機材データを作る**ので、設定なしでそのまま使える。

### 環境変数

| 変数 | 用途 | 未設定のとき |
|---|---|---|
| `SECRET_KEY` | セッションの署名 | 起動のたびに使い捨てを生成する（本番では必ず設定する） |
| `PORT` | 待ち受けポート | 5000 |
| `FLASK_ENV` | `production` でデバッグ off | デバッグ on |
| `SMTP_SERVER` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASSWORD` | メール通知 | 送信をスキップ |

## データの持ち方

| ファイル | 内容 | git |
|---|---|---|
| `equipment_data_sample.json` | 初期データの雛形（機材のみ） | 追跡する |
| `equipment_data.json` | 稼働中の貸出データ | **追跡しない** |
| `users_data.json` | 利用者とパスワードのハッシュ | **追跡しない** |

保存は JSON ファイル。貸出・返却・設定変更のたびに書き込み、プロセス終了時にも `atexit` で保存する。`/api/save` で手動保存もできる。

**永続ディスクのない環境に置くと、再起動でデータが消える。** 残したい場合は永続ストレージを割り当てる。

## 構成

```
app.py                     アプリ本体（ルーティング・予約ロジック・認証）
templates/
  index.html               一覧と予約フォーム
  login.html               ログイン
  register.html            新規登録
equipment_data_sample.json 初期データの雛形
```

## 動作確認

主要な経路を Flask のテストクライアントで確認している（20 項目）。

- 認証：未ログインで弾かれる／登録／ログイン／ログアウト後に弾かれる
- 予約：登録できる／重複期間を断る／利用中の予約を作れる
- 返却と取り消し：返却で消える／**これからの予約は返却では消えない**／取り消しでは消える
- 機材マスター：追加／改名／空きなら削除できる／**予約が残ると削除できない**

## リアルタイム更新について

貸出・返却・設定変更を反映するために Socket.IO を使っている。非同期方式は `threading` を指定した。eventlet や gevent は Python の版によって gunicorn から読めなくなることがあり、追加の依存に見合う利点が無かったため使っていない。WebSocket が張れない環境ではロングポーリングに落ちる。

## 既知の制限

- 同時アクセスの排他制御はしていない。多人数で同時に書き換えると後勝ちになる
- 日付は月日だけで持つため、1年以上先の予約は指定できない
- 削除した機材の予約履歴は残らない
